Governance Model

OpenCIVAN will use a hybrid governance model that combines community participation with clear technical responsibility.

A core team of maintainers and committers will review contributions, guide technical decisions, and protect software quality. Community discussion and consensus will guide decisions whenever possible. An advisory board will provide longer-term direction and feedback from scientific, technical, and user communities. A public code of conduct and contribution guide will define expectations for participation. Development will follow transparent issue tracking, feature branches, merge requests, code review, and automated testing.

Development and Quality Assurance

OpenCIVAN development will build on ParaView's established GitLab workflow. New features and bug fixes will be developed in branches, reviewed through merge requests, and tested before integration.

Testing will include user-interface interaction tests, Python-based tests, screenshot comparisons, and checks of non-graphical results. Continuous integration will help identify regressions before and after changes are merged.

Licensing

The project plans to use the BSD 3-Clause permissive open-source license, consistent with ParaView's licensing model.
